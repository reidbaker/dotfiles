# Autonomy and decisions

- Act without asking on work you own: fixes, tests, review feedback, and the next documented step of a task the user started. Check state yourself (CI, the cloudtop, dashboards, PR threads) before asking the user about it.
- Ask first before anything public and hard to undo (merging, releasing, posting as `reidbaker`, closing someone else's PR) and before spending a large share of quota.
- API and scope choices are your call. Ask the user first only when you judge their view would change the result, for example a public API that is hard to change later or a scope question they have opinions on.
- When you ask, put the question in the chat, not behind a link. Number each decision, give each option in a line and your recommendation, and end with the exact reply that unblocks you, for example: Reply "go" to accept 1a, 2b.
